### Task 5: Audit next-cache-components — LRU vs cacheLife/cacheTag

**Objective:** Tentukan apakah `use cache`/`cacheLife` bisa ganti LRU manual tanpa regresi 503-graceful.

**Files:**
- Read: `src/lib/sapa-client.ts:40-120` (LRU impl, TTL 10 mnt), `src/app/api/sapa/route.ts`, `src/app/api/kpi/route.ts`, `src/app/api/status/route.ts`

**Probe:**
```bash
grep -n "LRU\|CACHE_TTL\|fetchSapaData\|force-dynamic\|revalidate" src -R
cat src/lib/sapa-client.ts | grep -n "Map\|expiry\|Invalidate"
```

**Pertanyaan keputusan:**
- next-cache `cacheLife` + `cacheTag('sapa')` + `updateTag` untuk invalidasi vs LRU in-memory (hilang saat cold start Vercel serverless).
- Dampak ke `/api/status` (harus tetap real-time, bukan cached).
- PPR + `loading.tsx` untuk analytics/gis vs `dynamic ssr:false` yang ada.

**Hasil plan:** Matriks trade-off + rekomendasi: keep LRU + tambah `cacheLife` di layer route, ATAU full PPR. Tidak implement di plan.
